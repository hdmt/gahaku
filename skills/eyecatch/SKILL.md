# アイキャッチの作成

画像づくりは **OpenAI の画像 API**、指示と検証は **Claude Code** が受け持つ。

| 段階 | 担当 | 中身 |
|---|---|---|
| 1. 写真 | 画像 API | 場面から写真を生成する（文字なし） |
| 2. タイトル | 画像 API | 1の写真に、指定のタイトルを載せる（画像編集） |
| 3. 検証 | Claude Code | 仕上がりを見て、タイトルが1文字ずつ正しいか照合する |

投稿（WordPress へのアップロード、frontmatter への書き込みなど）は扱わない。呼び出した側に任せる。

## 0. 準備の確認

```bash
command -v gahaku && gahaku --version
```

- **gahaku が無い**: ユーザーに了承を取ってから `uv tool install git+https://github.com/hdmt/gahaku` で入れる
- **API キー**: 環境変数 `OPENAI_API_KEY` か `~/.config/gahaku/.env` に要る。無ければ、ユーザー自身に設定してもらう。**キーをチャットに貼ってもらわない**

## 1. 入力をそろえる

呼び出し元から受け取るか、無ければユーザーに聞く。

| 入力 | 例 | 無いとき |
|---|---|---|
| デザイン設定のパス | `sites/example.com/design.json` | 止まる。ユーザーと画風・文字デザインを決め、このプラグインの `examples/designs/` を手本に作る |
| タイトル | `"費用相場｜月額・初期費用の内訳"` | 聞く。`｜` の前がメイン、後ろがサブ |
| 出力先 | `output/example.com/eyecatch-1234.png` | 聞く |
| 費用の記録先 | `output/example.com/gahaku-cost.csv` | 省略してよい（記録しない） |

デザイン設定に `title.design` が無ければ、段階2はできない。先に決める。

## 2. 場面（scene）を決める

写真の場面を**英語2〜3文**で書く。記事の内容やタイトルから考え、決めきれなければユーザーに聞く。
画風・禁止事項はデザイン設定から足されるので、scene には**何が写っているか**だけを書く。

- 主題が一目で分かるもの。被写体は1〜2つに絞る（看板や車両が増えるほど偽の文字が出る）
- 実在の企業・制服・商品・人物が特定できる描写はしない

送る全文を確認し、scene をユーザーに見せて了承を取る。

```bash
gahaku prompt --design {design.json} --scene "..." --title-space --title "{タイトル}" [--cost-log {csv}]
```

## 3. 写真を生成し、チェックする

```bash
gahaku photo --design {design.json} --scene "..." --title-space \
  --out {出力先の拡張子の前に -photo を付けたもの} --n 2 [--cost-log {csv}] --json
```

- サイズはデザイン設定の `size`。変えるときは `--size 1200x630` や `--size og`（`sizes` の名前）
- 既存の画像とトーンを揃えたいときは `--ref` に渡す

生成された画像を**自分で開いて見る**。次のどれかがあれば scene を直して作り直す。

- 画面が途中で切れて、別の写真が並んだようになっている（コラージュ化）
- 文字・数字・ロゴが入っている（この段階では一切入れない）
- 顔・手・物の形が不自然

良い方を1枚選び、ユーザーに見せて確認を取る。

## 4. タイトルを載せる

```bash
gahaku title --design {design.json} --photo {選んだ写真} \
  --title "{タイトル}" --out {出力先} --n 2 [--cost-log {csv}] --json
```

- 画像に入れる文言を短くしたいときは `--main` `--sub` で上書きする（サブを消すなら `--sub ""`）
- サイト内でデザインを揃えたいときは `--ref` に既存のアイキャッチを渡す

結果の JSON の `text` が、照合の正解（label / main / sub）になる。

## 5. 検証（Claude Code）

仕上がりを**1枚ずつ自分で開き**、次を確認する。

1. **書き起こす**: 画像の文字を、見えたとおり1文字ずつ書き起こす。正解を見ながら読まない（思い込みで読み飛ばすため）
2. **照合する**: 書き起こしと `text` を1文字ずつ比べる。改行の位置は問わない
   - 似た別の字（例: 運↔連、業↔叢、機↔幾、援↔授）、画の欠け・余分な画、送り仮名・助詞の抜け、記号（「」｜・？）の違い
3. **余計な文字が無いか**: 指定外の文字・ロゴ・透かし・崩れた文字列が入っていないか
4. **デザイン**: 文字が枠からはみ出していないか、人物の顔にかかっていないか、小さく表示しても読めるか、写真が段階3から変わっていないか

結果は表にしてユーザーに見せる。

| 候補 | 書き起こし | 照合 | 余計な文字 | デザイン |
|---|---|---|---|---|

- **すべて OK の候補がある**: その候補を推薦する
- **誤字がある**: 段階4だけやり直す（写真はそのまま使う）。**やり直しは2回まで**。それでも誤字が残れば、ここまでの費用を添えてユーザーに判断を返す（`--main` で文言を短くする、`--model` や `--quality` を変える、など）

検証は Claude Code の目視なので見落としがありうる。**最終確認は人が行う**ことを必ず伝える。

## 6. 渡す

承認されたら、次を伝えて終わる。

- 採用した画像のパス
- scene
- かかった費用（各段階の JSON の `usd` の合計）

使わなかった候補を消すかどうかは、ユーザーに聞く。

## やらないこと

- 検証せずに画像を渡すこと
- 実在の人物・企業ロゴ・ブランドを画像に入れること
- 投稿・アップロード（呼び出した側の仕事）
