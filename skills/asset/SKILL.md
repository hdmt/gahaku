# 画像素材の作成

文字を入れない画像を作る。デザイン設定（JSON）で画風を揃え、用途ごとにサイズを変える。

## 0. 準備の確認

```bash
command -v gahaku && gahaku --version
```

- **gahaku が無い**: ユーザーに了承を取ってから `uv tool install git+https://github.com/hdmt/gahaku` で入れる
- **API キー**: 環境変数 `OPENAI_API_KEY` か `~/.config/gahaku/.env` に要る。無ければ、ユーザー自身に設定してもらう。**キーをチャットに貼ってもらわない**

## 1. 入力をそろえる

| 入力 | 例 | 無いとき |
|---|---|---|
| デザイン設定のパス | `sites/example.com/design.json` | 止まる。ユーザーと画風を決め、このプラグインの `examples/designs/` を手本に作る |
| 用途とサイズ | ヒーロー `1920x1080`、正方形 `1080x1080` | 聞く。デザイン設定の `sizes` に名前があればそれを使う |
| 何を描くか | 「窓辺で作業する人」 | 聞く |
| 出力先 | `public/images/hero.webp` | 聞く。拡張子で形式が決まる（.png / .webp / .jpg） |
| 背景 | 透過が要るか | ロゴの横やカードに重ねるイラストなら透過を勧める |

## 2. 場面（scene）を決める

何が写っているかを**英語2〜3文**で書く。画風・禁止事項はデザイン設定から足される。

- 用途に合わせて、文字やボタンを重ねる場所が要るなら、その旨を scene に書く（例: "Leave the left third as soft, empty background."）
- 被写体は1〜2つに絞る。実在の企業・商品・人物が特定できる描写はしない

送る全文を確認し、scene をユーザーに見せて了承を取る。

```bash
gahaku prompt --design {design.json} --scene "..." --size {サイズ} [--cost-log {csv}]
```

## 3. 生成する

```bash
gahaku photo --design {design.json} --scene "..." --size {サイズ} \
  --out {出力先} --n 2 [--background transparent] [--ref {参考画像}] [--cost-log {csv}] --json
```

- 透過背景（`--background transparent`）は .png か .webp で保存する
- 既存の素材とトーンを揃えたいときは `--ref` に渡す（複数可）
- 同じ画風で複数のサイズが要るときは、良かった1枚を `--ref` にして、サイズを変えて作り直す

## 4. チェックして渡す

生成された画像を**自分で開いて見る**。次があれば scene を直して作り直す。

- 文字・数字・ロゴ・透かしが入っている
- 顔・手・物の形が不自然
- 透過のはずが背景が残っている、または被写体の縁が欠けている
- 文字やボタンを重ねる場所が、予定どおり空いていない

候補を並べてユーザーに見せ、選んでもらう。採用した画像のパス、scene、費用（JSON の `usd` の合計）を伝えて終わる。
使わなかった候補を消すかどうかは、ユーザーに聞く。

## やらないこと

- 画像に文字を入れること（タイトル入りは eyecatch スキル）
- 実在の人物・企業ロゴ・ブランドを画像に入れること
- サイトへの配置やアップロード（呼び出した側の仕事）
